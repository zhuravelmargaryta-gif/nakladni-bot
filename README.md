# 🧾 Бот обліку накладних

Telegram-бот, у який співробітники надсилають **фото накладних**. Бот розпізнає реквізити за допомогою ШІ
(Google Gemini) і зберігає їх у базу. У ньому можна переглядати, фільтрувати й редагувати накладні,
вести **рух накладної** (відправлено, повернулась підписана, оплачено, повернення…), дивитися
**історію змін** і вивантажувати все в **Excel**. За бажанням накладні автоматично потрапляють в **Odoo**.

---

## Що потрібно

- Комп'ютер з **Windows 10/11**, який працює, поки потрібен бот, і має інтернет.
- **Python 3.12**: https://www.python.org/downloads/
  ⚠️ Під час встановлення обов'язково поставте галочку **«Add python.exe to PATH»**.

---

## Крок 1. Створіть бота в Telegram і отримайте токен

1. Відкрийте в Telegram [@BotFather](https://t.me/BotFather) і натисніть **Start**.
2. Надішліть команду `/newbot`.
3. Введіть назву бота (наприклад, `Накладні ТОВ Ромашка`) і його адресу латиницею, яка закінчується на `bot`
   (наприклад, `romashka_invoices_bot`).
4. BotFather надішле **токен** на зразок `7123456789:AAHk3...`. Скопіюйте його.
   🔒 Нікому не показуйте токен: з ним можна керувати ботом.

## Крок 2. Отримайте ключ Google Gemini

1. Відкрийте https://aistudio.google.com/apikey і увійдіть у свій Google-акаунт.
2. Натисніть **Create API key** і скопіюйте ключ (починається з `AIza...`).

Безкоштовного тарифу Gemini зазвичай достатньо для десятків накладних на день.

## Крок 3. Перший запуск

1. Розпакуйте папку з ботом, наприклад у `C:\InvoiceBot`.
2. Двічі клацніть **`run.bat`**.
   - Перший запуск триває 1–2 хвилини: бот створює середовище і встановлює бібліотеки.
   - Потім у **Блокноті** відкриється файл налаштувань `.env`.
3. Вставте токен у рядок `BOT_TOKEN=` і ключ у рядок `GEMINI_API_KEY=`. Збережіть файл (**Ctrl+S**) і закрийте Блокнот.
4. Знову двічі клацніть **`run.bat`**. Коли з'явиться напис «✅ Бот працює», бот готовий.
5. Відкрийте свого бота в Telegram, натисніть **Start** і надішліть фото накладної.

> Поки вікно `run.bat` відкрите, бот працює. Якщо його закрити, бот зупиниться.
> Щоб бот стартував разом з комп'ютером, покладіть ярлик на `run.bat` у папку автозавантаження
> (**Win+R** → `shell:startup` → Enter).

## Крок 4. Обмежте доступ ⚠️

Поки рядок `ALLOWED_USERS` порожній, ботом може користуватися **будь-хто**, хто знайде його в Telegram.
Тоді сторонні люди бачитимуть усі ваші накладні.

1. Кожен співробітник пише боту `/myid`, і бот показує його числовий ID.
2. Впишіть усі ID через кому у файл `.env`:
   ```
   ALLOWED_USERS=123456789,987654321,555000111
   ADMIN_IDS=123456789
   ```
   - `ALLOWED_USERS`: хто може користуватися ботом. Решта бачить «Немає доступу».
   - `ADMIN_IDS`: хто може редагувати й видаляти **будь-які** записи. Звичайні користувачі можуть змінювати лише свої.
     Якщо цей рядок порожній, усі можуть змінювати все.
3. Закрийте вікно бота і знову запустіть `run.bat`. Після будь-якої зміни `.env` бота треба перезапускати.

Ще одне корисне налаштування: `OUR_COMPANY_CODE` (ЄДРПОУ вашої компанії). Якщо у вихідній накладній
постачальник — ви, контрагентом стане покупець.

## Як користуватися

| Дія | Як |
|---|---|
| Додати накладну | Надіслати фото, зображення файлом або PDF |
| Знайти | Написати в чат номер, назву контрагента або ЄДРПОУ (регістр не важливий) |
| Відкрити запис №12 | Написати `#12` |
| Фільтри | Кнопки внизу: 🏢 контрагент, 📅 період, 📌 статус. Вони поєднуються між собою, і в кожного користувача свій набір |
| Підсумки та Excel | 📊 і 📥: рахуються за поточним фільтром |
| Позначити, що проблему вирішено | У картці: **✅ Вирішено** → напишіть, як вирішили, та/або додайте фото. Повернути назад: **🔓 Відкрити знову** |
| Лише відкриті / вирішені | Над списком накладних: перемикач **🔴 Відкриті · 🟢 Вирішені · Усі** |
| Подія руху | У картці накладної: ➕ Подія → тип → сума → дата → коментар та/або фото |
| Історія | 🕓 у картці: хто, коли і що змінив («було → стало») |
| Журнал дій | 🕓 у меню: останні 20 дій усіх користувачів |

Кожна нова накладна вважається **🔴 відкритою проблемою**, доки хтось не натисне «✅ Вирішено».
Щодня о `REMINDER_TIME` (за замовчуванням 09:00) бот надсилає адміністраторам список проблем,
відкритих довше за `REMINDER_MIN_DAYS` днів. Налаштувати або вимкнути нагадування можна у `.env`.

Видалення «м'яке»: накладна зникає зі списків, підсумків і Excel, але її можна **↩️ Відновити**.

**Типи подій** описані у файлі `invoice_bot/event_types.py`. Щоб додати новий тип, допишіть туди один рядок
за зразком інших (ключ латиницею, до 16 символів) і перезапустіть бота.

## Крок 5. Резервна копія бази

Усі дані зберігаються в одному файлі `invoices.db` у папці бота.
Фото лишаються на серверах Telegram, у базі записано лише посилання на них.

- **Найпростіше:** двічі клацніть **`backup.bat`**. Копія з датою з'явиться в папці `backups\`.
  Так можна робити навіть під час роботи бота.
- Регулярно копіюйте папку `backups\` на флешку або в хмару (Google Drive, OneDrive).
- **Відновлення:** зупиніть бота, перейменуйте потрібну копію на `invoices.db`, покладіть її в папку бота
  замість старої і запустіть `run.bat`.

Оновлення бота не ламає стару базу: відсутні колонки й таблиці додаються автоматично.
Перед оновленням усе одно зробіть копію.

## Крок 6. Підключення Odoo (необов'язково)

Без Odoo бот повністю працює сам. Якщо Odoo підключено:

- нова накладна автоматично створюється в Odoo як **чернетка рахунку постачальника**
  з контрагентом, номером, датою, товарами і фото;
- контрагент шукається за ЄДРПОУ, потім за назвою; якщо його немає, бот його створює;
- події руху накладної додаються нотатками в чат рахунку;
- після редагування накладної в боті натисніть **🔄 Оновити в Odoo**. Оновлюються лише **чернетки**,
  проведені рахунки бот не змінює;
- дублікати автоматично не відправляються;
- видалення в боті **не** видаляє рахунок в Odoo.

### Де взяти дані

1. **ODOO_URL**: адреса, яку ви відкриваєте в браузері, наприклад `https://mycompany.odoo.com`.
2. **ODOO_DB**: назва бази. Для Odoo Online це зазвичай піддомен (`mycompany`). Точну назву показує
   сторінка `https://mycompany.odoo.com/web/database/selector`, а також розділ «Налаштування → Активувати режим розробника».
3. **ODOO_USER**: email, з яким ви входите в Odoo.
4. **ODOO_API_KEY**: в Odoo натисніть на свій аватар (вгорі праворуч) → **Мій профіль / Налаштування** → вкладка
   **Безпека облікового запису** → **Новий API-ключ**. Введіть пароль, дайте ключу назву (наприклад, «Telegram-бот»)
   і скопіюйте ключ. Його показують лише один раз.

> ⚠️ На **безкоштовному тарифі Odoo Online («One App Free»)** зовнішній API може бути недоступний.
> Потрібен тариф Standard/Custom, Odoo.sh або власний сервер. Підходять Odoo 16, 17 і 18.

Впишіть ці дані в `.env`, перезапустіть бота і надішліть йому `/odoo_test`, щоб перевірити з'єднання.

### Додаткові налаштування Odoo

| Параметр | Що робить |
|---|---|
| `ODOO_AUTO_SYNC` | `true`: відправляти нові накладні автоматично; `false`: лише кнопкою |
| `ODOO_PARTNER_CODE_FIELD` | Поле контрагента з ЄДРПОУ: `company_registry` (за замовчуванням) або `vat` |
| `ODOO_PURCHASE_TAX_ID` | ID податку «ПДВ 20%» на закупівлю. Якщо задано, ціни в рядках вважаються **без** ПДВ і до них додається цей податок. Якщо порожньо, ціни йдуть як є, без податку |
| `ODOO_JOURNAL_ID` | ID журналу закупівель (якщо їх кілька) |
| `ODOO_EXPENSE_ACCOUNT_ID` | ID рахунку витрат для рядків |

Щоб дізнатися ID податку чи журналу, увімкніть в Odoo режим розробника, відкрийте потрібний податок і подивіться
на число в адресному рядку (`.../account.tax/7` означає ID 7).

Команда адміністратора **`/odoo_sync`** відправляє в Odoo всі невідправлені, змінені й помилкові накладні.

## Якщо щось не так

| Проблема | Що робити |
|---|---|
| Вікно `run.bat` одразу закривається або пише «Python не знайдено» | Перевстановіть Python з галочкою «Add python.exe to PATH» |
| «Не заповнено BOT_TOKEN» | Відкрийте `.env` у Блокноті і вставте токен |
| Бот не відповідає | Перевірте, чи відкрите вікно `run.bat` і чи є інтернет |
| «Немає доступу» | Додайте ID користувача в `ALLOWED_USERS` і перезапустіть бота |
| «Вичерпано ліміт запитів до ШІ» | Зачекайте хвилину, бо безкоштовний ліміт Gemini обмежений за хвилину/добу |
| Погано розпізнає | Фотографуйте рівно, при гарному світлі, щоб у кадр потрапив увесь аркуш. Найкраще надсилати фото файлом або PDF |

Технічний журнал роботи пишеться в папку `logs\` (`bot.log`). Якщо щось зламалося, надішліть цей файл розробнику.

## Для розробника

```
main.py                  точка входу
invoice_bot/
  config.py              налаштування з .env
  event_types.py         типи подій руху накладної
  parsing.py             розбір і формат дат, сум, кодів
  db.py                  SQLite: схема й автоміграція, фільтри, історія, події
  recognition.py         Gemini, structured output (Pydantic)
  cards.py               тексти повідомлень і клавіатури
  export.py              Excel (openpyxl)
  odoo.py                XML-RPC клієнт і синхронізація
  bot.py                 обробники Telegram
tests/                   pytest, зокрема фейковий XML-RPC сервер Odoo
```

Запуск тестів:

```bash
pip install -r requirements-dev.txt
```

```bash
python -m pytest
```

Перехід на PostgreSQL: увесь SQL зосереджений у `db.py`. Єдине специфічне для SQLite місце — функція
`ulower()` для пошуку кирилицею без урахування регістру (у PostgreSQL її замінює `lower()`/`ILIKE`).
